# 論文整稿室

以瀏覽器處理 Word 論文的格式修改工具。無後端文件儲存、無 API 金鑰；論文及使用者上傳的規範只在瀏覽器記憶體內處理。

## 功能

- 匯入未加密的 .docx 論文（30 MB 以下）。
- 讀取文字型 PDF、.docx、UTF-8 TXT 規範（15 MB 以下）。
- 附帶使用者提供之清大 114 年 5 月 29 日修正版規範全文與預設辨識。
- 擷取明確且一致的紙張、邊界、字型、字級、行距、黑色文字及頁尾置中要求；可調整。
- 選擇正文起點，保留前置段落及標題、表格、圖說與公式的文字樣式。
- 直接修改原 DOCX 中的 OOXML，保留其他封裝內容；輸出前比對本文文字與公式。
- 套用前先列出預計修改摘要與實際段落、節及頁尾位置，按下確認後才產生 Word。調整任何設定即清除先前預覽。
- 上傳成功的規範原文會記住於此瀏覽器，可透過下拉選單重用；以內容摘要去重，論文不儲存。儲存失敗會提示，不影響本次使用。
- 下載修改後的 Word 及條列式修改說明（含影響數量、規則來源及待確認項目）。

## 限制

規範解析是保守的文字規則擷取，沒有使用生成式 AI，也不會執行文件中的操作指令。不能承諾辨識任意學校的全部自然語言規範；有歧義或未辨識的項目需使用者對照原文指定。掃描 PDF 需要先 OCR。

文字格式作用於一般段落。頁面與頁尾以節為單位；正文與前置頁在同一節時，該節整體受影響。不自動重排章節、不補簽章文件、不校訂引用格式、不重新編排圖表。頁首頁碼不移除。Word 分頁與欄位須在 Word 裡更新並檢查。字型須在使用者電腦上安裝。

## 驗證

`create-fixture.py` 建立開發用測試資料，`verify.cjs` 測試真實清大 PDF 的 11 項設定、DOCX 下載、修改報告、本文文字與公式完整性、圖片位元組、前置節與表格保留、頁尾圖片關聯、手機版寬度、損毀文件與矛盾要求，以及預览／確認結果一致、失效預覽阻擋、重新整理後規範重用、重複上傳去重。測試檔位於忽略的 test-output 目錄，不部署。

DOCX 通過 Python-docx 重新開啟驗證，並使用本機 Microsoft Word 背景開啟、更新欄位、轉出兩頁 PDF，再逐頁檢視文字、圖表、公式與頁碼。網站本身不含 Word 分頁引擎，使用者自己的論文仍須開啟 Word 確認。WebMCP 僅在支援 document.modelContext 的瀏覽器註冊唯讀狀態工具；本機測試環境無此原生 API，未執行原生 WebMCP 驗證。

## 本機

`node preview.cjs`，預覽網址為 http://127.0.0.1:4185。部署靜態入口為 dist/index.html，所有執行時依賴均在 dist/vendor。
